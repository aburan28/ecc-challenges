Reading these numbers

A point is counted once it is stored. {% if v2 %}Points from the new worker are also checked one by one against the curve before they enter collision search; {% endif %}ECC2K-130 points from the original worker are checked by replaying sampled batches.

Each distinguished point (DP) stands for the average walk length between two of them, so estimated work is points times that length. On the ECC2K-130 walk that is 228.4 at DP32, where DP32 means the x-coordinate has Hamming weight 32 or less. DP30 and DP34 runs use their own stored thresholds. The all-curve walk uses 2t for a threshold of t zero bits. The percentage compares that with the expected work of the walk being run. For ECC2K-130 that is Certicom's figure. The all-curve walk does not yet use the negation or Frobenius maps, so it expects √2 times Certicom's figure on most curves and √(2m) times on Koblitz curves over GF(2m). ECC2K-130 shows two figures: the combined progress including points imported from the earlier private run first, with public uploads alone underneath. The imported points walk the same function and count toward the same collision. It is an estimate from point counts, not a count of verified steps.

Rho is a random search, so 100% is not a finish line: a collision can arrive earlier or later. "Collision odds" is the probability that one would have appeared by now, 1 − e−π/4·x² for work fraction x (details). Points per hour is averaged over the last {{ snapshot.rate_window_hours if snapshot else 24 }} hours because workers upload in large batches.
