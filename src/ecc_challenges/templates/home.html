The method

How the search works

Each challenge gives a curve, a base point G and a target point Q. The goal is the integer d with Q = dG. The Pollard rho method takes a pseudo-random walk on the curve where every point is a known combination aG + bQ. When two walks reach the same point, the two combinations give d.

Storing every step is impossible, so workers report only distinguished points: points with a rare property that is cheap to test, such as a low Hamming weight on ECC2K-130. Two walks that meet stay together and reach the same next distinguished point, so the server only has to compare those.

What gets checked

    {% if multicurve_enabled %}
  • Every uploaded point is checked against the curve equation and its stated relation R = aG + bQ before it is indexed.
    • {% endif %}
  • {% if multicurve_enabled %}ECC2K-130 workers on the original walk: one record from the{% else %}One record from the{% endif %} first batch of every run is replayed independently. Later batches are sampled at random, 1 in 128.
  • A failed replay suspends the run, revokes its key and removes its points from collision search.
  • Any collision is recomputed from both trails, and the resulting d is checked against the published Q before it is reported.

Raw uploads and check results are kept so the work can be audited later.
