The method

How the search works

Each challenge gives a curve, a base point G and a target point Q. The goal is the integer d with Q = dG. Pollard's rho method takes a pseudo-random walk on the curve where every point is a known combination aG + bQ. When two walks reach the same point, the two combinations give d.

Keeping every step is impossible, so workers report only distinguished points, ones whose encoding starts with a fixed run of zero bits. Two walks that meet stay together until the next distinguished point, so the server only has to compare those.

  • Every uploaded point is checked against the curve equation and its stated relation R = aG + bQ before it is indexed.
    • {% endif %}
  • {% if multicurve_enabled %}ECC2K-130 workers on the original walk: the{% else %}The{% endif %} first batch of every run is replayed independently. Later batches are replayed at random, 1 in 128.
  • A failed replay suspends the run, revokes its key and removes its points from collision search.
  • Any collision is recomputed from both trails, and the resulting d is checked against the published Q before it is reported.

Raw uploads and check results are kept so the work can be audited later.
