2. Run the worker

{% if multicurve_enabled %}Use Docker or a native Windows or macOS worker.{% else %}The current public campaign needs Docker and the NVIDIA Container Toolkit.{% endif %}

{% if multicurve_enabled %}
{% endif %} 
# one directory per GPU; keep it between restarts
GPU_ID=0
CAMPAIGN={{ selected_campaign|default("ecc2k-130") }}
mkdir -p "$PWD/ecc-data-$CAMPAIGN-$GPU_ID"

docker run --gpus all --restart unless-stopped \
  --user "$(id -u):$(id -g)" \
  -e ECC_GPU="$GPU_ID" \
  -e ECC_CAMPAIGN="$CAMPAIGN" \
  -e ECC_PROTOCOL={{ 2 if multicurve_enabled else 1 }} \
  -e ECC_API_URL=https://ecc-challenges.com \
  -v "$HOME/.config/ecc-challenges/api-key:/run/secrets/ecc_api_key:ro" \
  -v "$PWD/ecc-data-$CAMPAIGN-$GPU_ID:/data" \
  {{ worker_image }}
  • For more GPUs, start one container per card with a different GPU_ID and its own data directory. Never reuse or wipe a directory while its run is active.
    • {% if multicurve_enabled %}
  • On an amd64 CPU host, use this same image without --gpus all or -e ECC_GPU; it selects the CPU backend. New builds use OMP_NUM_THREADS to limit CPU threads.
    • {% endif %} {% if multicurve_enabled %}
  • On Windows, run the native CPU worker or build its optional CUDA engine. On macOS, run the native Metal worker. Both use the same persistent checkpoint format; follow the native setup steps.
    • {% endif %}
  • Kubernetes, systemd, Podman, Slurm, Modal or no Docker at all: see Running a worker. On RunPod or similar, use the same image, mount persistent storage at /data, and pass the key as a mounted file or the ECC_API_KEY secret.
  • If the server answers 429 or 503, the worker waits and retries. It keeps unsent points on disk.

3. Check it's working

Within a few minutes your run should appear under Your runners above and in the active count on the status page. The worker logs its run ID and each accepted upload. Problems or odd results: open an issue.
