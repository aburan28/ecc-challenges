NVIDIA GPU, with Docker

Needs Docker and the NVIDIA Container Toolkit. Save your key as shown in step 1 first.

{% if sigma_worker %}

DP34 is recommended for new NVIDIA workers and reports points more frequently. DP32 and DP30 are also accepted. All three can match compatible points from the earlier ECC2K-130 search.

Use a separate directory for each threshold. Resume an existing run with its original command and directory. CPU and Mac workers below use a separate search and do not use this setting.

{% endif %} 
# one directory per GPU; keep it between restarts
GPU_ID=0
CAMPAIGN={{ selected_campaign|default("ecc2k-130") }}
{% if sigma_worker %}DP_WEIGHT={{ selected_dp_weight }}
{% endif %}mkdir -p "$PWD/ecc-data-$CAMPAIGN{% if sigma_worker %}-dp$DP_WEIGHT{% endif %}-$GPU_ID"

docker run --gpus all --restart unless-stopped \
  --user "$(id -u):$(id -g)" \
  -e ECC_GPU="$GPU_ID" \
  -e ECC_CAMPAIGN="$CAMPAIGN" \
  -e ECC_PROTOCOL={{ 1 if sigma_worker else 2 }} \
{% if sigma_worker %}  -e ECC_DP_WEIGHT="$DP_WEIGHT" \
{% endif %}  -e ECC_API_URL=https://ecc-challenges.com \
  -v "$HOME/.config/ecc-challenges/api-key:/run/secrets/ecc_api_key:ro" \
  -v "$PWD/ecc-data-$CAMPAIGN{% if sigma_worker %}-dp$DP_WEIGHT{% endif %}-$GPU_ID:/data" \
  {{ worker_image }}
  • For more GPUs, start one container per card with a different GPU_ID and its own data directory. Never reuse or wipe a directory while its run is active.
    • {% if multicurve_enabled and not sigma_worker %}
  • On an x86-64 machine without a GPU, use this same command without --gpus all and -e ECC_GPU; it runs on the CPU. OMP_NUM_THREADS limits the threads.

CPU, with Docker (x86-64 or ARM64)

The smaller CPU image runs all 24 curves on either architecture, including Graviton instances. Save your key as shown in step 1 first.

CAMPAIGN={{ selected_campaign }}
mkdir -p "$PWD/ecc-cpu-$CAMPAIGN"

docker run --restart unless-stopped \
  --user "$(id -u):$(id -g)" \
  -e ECC_BACKEND=cpu -e ECC_PROTOCOL=2 \
  -e ECC_CAMPAIGN="$CAMPAIGN" \
  -e ECC_API_URL=https://ecc-challenges.com \
  -v "$HOME/.config/ecc-challenges/api-key:/run/secrets/ecc_api_key:ro" \
  -v "$PWD/ecc-cpu-$CAMPAIGN:/data" \
  {{ cpu_worker_image }}

Without Docker (any CPU, x86-64 or Arm)

One command downloads and builds the worker, asks for your key and starts it. It uses CUDA if nvcc is installed. Needs python3 3.10+ and a C++ compiler (sudo apt install python3 g++ or sudo dnf install python3 gcc-c++).

curl -fsSL https://ecc-challenges.com/install.sh | {{ sh_env }}sh

  • Needs Python 3.10 or newer from python.org or brew install python; the one that ships with macOS can be too old.

Native worker

Windows 10 or 11, x64 or ARM64. Runs on the CPU, or on an NVIDIA GPU if the CUDA toolkit is installed. In PowerShell:

# once: Python, CMake and the C++ build tools
winget install -e --id Python.Python.3.12
winget install -e --id Kitware.CMake
winget install -e --id Microsoft.VisualStudio.2022.BuildTools --override "--quiet --wait --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended"

# then, in a new PowerShell window
{{ ps_env }}irm https://ecc-challenges.com/install.ps1 | iex

The installer asks for your key, saves it where only you can read it and offers to start the worker. Stop it with Ctrl-C.

NVIDIA GPU, with Docker Desktop

Install Docker Desktop with the WSL 2 backend and a current NVIDIA driver. Then open an Ubuntu (WSL) terminal, save your key as shown in step 1 and run the Docker command from the Linux tab.

The same worker, packaged for longer-running setups. Each recipe is in Running a worker.

  • Docker Compose: several workers on one machine.
  • systemd: a Linux server, started at boot, no containers.
  • Kubernetes, Podman, Slurm.
  • Modal, RunPod or any GPU cloud: use the Docker image above, mount persistent storage at /data, and pass the key as a mounted file or the ECC_API_KEY secret.

If the server answers 429 or 503, the worker waits and retries. It keeps unsent points on disk.
