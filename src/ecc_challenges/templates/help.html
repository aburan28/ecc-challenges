Before changing anything

Record the campaign, run ID, worker image or version, operating system, and exact error message. Keep the surrounding log lines and the time the problem occurred.

Keep API keys, authorization headers and signed upload URLs private. Never delete a checkpoint to get past an error.

Common problems

Uploads are waiting or the count has not changed

The worker logs accepted uploads and keeps unsent points on disk. A 429 response asks it to slow down; a temporary 503 makes it wait and retry. Check the campaign's availability on the status page. The status counts refresh about once a minute and cover this gateway.

A key is rejected

Check that the worker reads the intended key file and that the key has not been revoked. Manage keys in your dashboard. Revoking a key stops uploads from every worker using it.

A worker will not resume

Use the same data directory, campaign and worker identity. Only one process may use a worker's directory at a time. Stop the duplicate process cleanly; preserve all state if the worker reports conflicting checkpoints. The cloud guide covers persistent volumes and migration errors.

A result or count looks wrong

Archived points and independently verified work are different counts. The status page explains the figures, and open problems records known validation and capacity gaps. Historical solved results link to their published key and public point from the challenge tables.
